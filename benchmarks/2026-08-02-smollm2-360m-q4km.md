# SmolLM2-360M Q4_K_M: CPU vs GPU Benchmark

Date: 2026-08-02

## Test platform

- Device: NVIDIA Jetson Nano Developer Kit, 4 GB
- GPU: NVIDIA Tegra X1, Maxwell, compute capability 5.3
- CUDA: 10.2.300
- `llama.cpp`: b5050, commit `23106f94e`
- Model: SmolLM2-360M-Instruct Q4_K_M GGUF
- Model size: 256.35 MiB
- Parameters: 361.82 M
- CPU threads: 4
- Prompt test: `pp128`
- Generation test: `tg64`

## Commands

### Full GPU offload

```bash
./build-nano/bin/llama-bench \
  -m /data/models/SmolLM2-360M-Instruct-Q4_K_M.gguf \
  -ngl 99 \
  -t 4 \
  -p 128 \
  -n 64
```

### CPU-only execution

```bash
./build-nano/bin/llama-bench \
  -m /data/models/SmolLM2-360M-Instruct-Q4_K_M.gguf \
  -ngl 0 \
  -t 4 \
  -p 128 \
  -n 64
```

## Results

| Mode | GPU layers | Prompt processing (`pp128`) | Token generation (`tg64`) |
|---|---:|---:|---:|
| CUDA full offload | 99 | 154.11 ± 2.54 t/s | 14.13 ± 0.27 t/s |
| CPU only | 0 | 135.21 ± 1.92 t/s | 7.08 ± 0.03 t/s |

## Derived comparison

- Prompt-processing speedup: `154.11 / 135.21 = 1.14×`
- Prompt-processing improvement: approximately `14.0%`
- Token-generation speedup: `14.13 / 7.08 = 2.00×`
- Token-generation improvement: approximately `99.6%`
- Approximate time to process 128 prompt tokens:
  - GPU: `0.83 s`
  - CPU: `0.95 s`
- Approximate time to generate 64 tokens:
  - GPU: `4.53 s`
  - CPU: `9.04 s`

## Interpretation

Full CUDA offload provides only a moderate improvement for prompt ingestion because this small model and short prompt already run efficiently on the four Cortex-A57 CPU cores. Autoregressive token generation benefits much more: the GPU almost exactly doubles generation throughput.

The benchmark table labels the architecture as `llama 3B`, but the reported parameter count is correctly `361.82 M`. This is a classification quirk in the pinned `llama.cpp` revision, not the actual model size.

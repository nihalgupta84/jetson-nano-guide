# Cloudflare Remote Access and Automatic Startup

Verified on 2026-08-02.

This chapter documents the working production-style setup that exposes the Jetson Nano local LLM securely at:

```text
https://ai.nihalgupta.me
```

The endpoint was verified from a phone using mobile data, outside the local Wi-Fi network.

## Final architecture

```text
Remote browser or phone
        |
        v
https://ai.nihalgupta.me
        |
Cloudflare Access authentication
        |
Cloudflare Tunnel
        |
http://127.0.0.1:8080
        |
llama-server
        |
Qwen2.5-0.5B-Instruct Q4_K_M
        |
Jetson Nano CUDA GPU
```

No router port forwarding or public IP address is required.

## Cloudflare configuration

### Access application

Create a self-hosted Cloudflare Access application for:

```text
ai.nihalgupta.me
```

Use an Allow policy restricted to the intended account or exact email address. Do not use an unrestricted `Everyone` Allow policy.

### Tunnel route

Use the dedicated tunnel:

```text
jetson-nano-llm
```

Add a published application route:

```text
Hostname: ai.nihalgupta.me
Service type: HTTP
Service URL: http://127.0.0.1:8080
```

### cloudflared service

Install the tunnel token as a system service using the command generated by the Cloudflare dashboard. Never commit or publish the token.

Verify:

```bash
sudo systemctl enable --now cloudflared
sudo systemctl status cloudflared --no-pager
sudo journalctl -u cloudflared -n 50 --no-pager
```

Expected state:

```text
Active: active (running)
```

The dashboard should report the tunnel as Healthy.

## llama-server systemd service

Create `/etc/systemd/system/llama-server.service`:

```ini
[Unit]
Description=Jetson Nano llama.cpp Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/data/llama.cpp
ExecStart=/data/llama.cpp/build-nano/bin/llama-server \
  -m /data/models/qwen2.5-0.5b-instruct-q4_k_m.gguf \
  -ngl 99 \
  -c 512 \
  -t 4 \
  -n 256 \
  --host 127.0.0.1 \
  --port 8080
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Enable and start it:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now llama-server
```

Verify:

```bash
sudo systemctl status llama-server --no-pager
curl http://127.0.0.1:8080/health
ss -lntp | grep 8080
```

The listener should be bound only to:

```text
127.0.0.1:8080
```

This prevents direct LAN or public access to the raw service. Cloudflare Tunnel reaches it locally.

## Reboot verification

Reboot:

```bash
sudo reboot
```

After the Nano returns:

```bash
sudo systemctl status llama-server --no-pager
sudo systemctl status cloudflared --no-pager
curl http://127.0.0.1:8080/health
```

Then test remotely:

```text
https://ai.nihalgupta.me
```

The verified result is:

1. Cloudflare Access requests authentication.
2. After login, the llama-server interface opens.
3. Prompts are answered by Qwen on the Jetson Nano GPU.
4. Both `cloudflared` and `llama-server` recover automatically after reboot.

## Security notes

- Never commit Cloudflare tunnel tokens.
- Rotate a token if it appears in terminal output, shell history, screenshots, chat, or logs.
- Keep the origin bound to `127.0.0.1`, not `0.0.0.0`, when using Cloudflare Tunnel.
- Keep Cloudflare Access enabled for the hostname.
- Do not configure router port forwarding for port 8080.
- Model files and credentials must remain outside Git.

## Troubleshooting

### Cloudflare shows 502 Bad Gateway

The tunnel is connected but the local origin is unavailable. Check:

```bash
sudo systemctl status llama-server --no-pager
curl http://127.0.0.1:8080/health
```

### Tunnel is Down

Check:

```bash
sudo systemctl status cloudflared --no-pager
sudo journalctl -u cloudflared -n 100 --no-pager
```

### The interface works locally but not remotely

Confirm the tunnel route points to:

```text
http://127.0.0.1:8080
```

and that the hostname is exactly:

```text
ai.nihalgupta.me
```

### Server does not return after reboot

Check whether both services are enabled:

```bash
systemctl is-enabled llama-server
systemctl is-enabled cloudflared
```

Both should return:

```text
enabled
```
